# Підготовка до захисту DOGFIGHT — лабораторні 01–08

> Цей конспект пояснює архітектуру інтегрованого проєкту. Фактичні результати продуктивності, coverage, e2e, remote-play та deployment потрібно отримати запуском тестів і демонстрацією; не називайте їх виконаними без вимірювань.

## Загальна ідея

DOGFIGHT — браузерна top-down multiplayer space arena. Клієнт відображає Canvas і надсилає наміри гравця (поворот, тяга, постріл). Сервер є authoritative: він сам змінює світ і розсилає snapshots. `shared/` містить логіку симуляції та протокол, яку використовують обидві сторони.

## Lab 01 — Event Loop and Game Loop

- JavaScript у вкладці виконується в одному основному потоці. Синхронний код повинен завершитися, перш ніж event loop виконає наступну задачу.
- Promise callbacks — microtasks; `setTimeout` — task/macrotask. Microtasks спорожнюються перед наступним task/render opportunity.
- `requestAnimationFrame` викликається перед paint і синхронізований з дисплеєм; `setInterval(16)` не гарантує синхронізацію.
- `client/src/main.ts`: `requestAnimationFrame`, accumulator, `STEP=1/60`, clamp elapsed до 250 ms, HUD FPS/steps/frame ms.
- `shared/src/sim/world.ts`: симуляція не імпортує DOM або Canvas.
- Що показати: відкрити DevTools Performance, порівняти нормальний цикл з busy wait; пояснити, чому 100 ms блокування не можна обійти в тому самому потоці.

**Питання:** Чим task відрізняється від microtask? Для чого accumulator? Що означає alpha? Чому `let` і `var` відрізняються в циклі callback? Що змінює `type="module"`?

## Lab 02 — Objects, Prototypes, and this

- `Vector2` — векторні операції; `Entity`/`Ship` — сутності; `World` зберігає сутності в `Map`, `ofKind()` — generator.
- Кулі мають TTL; зіткнення коло-коло зменшує HP; знищений корабель відроджується.
- `this` визначається способом виклику функції. Передавання `ship.fire` як callback може втратити контекст; arrow wrapper або `bind` фіксує його.
- Composition корисна для поведінок, які не утворюють природну ієрархію.

**Питання:** Що таке prototype delegation? Чим `Map` кращий за звичайний object як entity store? Чому `this` залежить від call-site? Чим shallow copy відрізняється від deep copy?

## Lab 03 — Async JavaScript, Assets, and Lobby

- Асинхронні операції не повинні блокувати кадр. `Promise.all` завантажує незалежні ресурси паралельно.
- `client/src/assets/loader.ts`: fetch JSON, зображень і аудіо, AbortSignal, retry/backoff, прогрес `loadAll`.
- `audio.ts` відкриває AudioContext після дії користувача. Симуляція не повинна імпортувати UI/audio.
- Клієнтський lobby UI дозволяє задати callsign і room; API серверу повертає список кімнат.

**Питання:** Що робить `Promise.all`? Чому потрібен AbortController? Чому не можна чекати `image.complete` у циклі while? Коли повторювати HTTP-запит недоцільно?

## Lab 04 — Node.js Runtime and WebSocket Server

- `server/src/index.ts`: Node HTTP, API `/api/rooms`, `/health`, `/ready`, `/metrics`, `/api/stats`; WebSocket `/ws`.
- `Room` extends EventEmitter; повідомлення проходять Zod validation; є join timeout, token bucket, payload cap, origin/IP/room limits.
- Події кімнати записуються у NDJSON через Transform і stream pipeline. Replay endpoint віддає файл потоком.
- SIGINT/SIGTERM зупиняють tick loop, закривають sockets і HTTP server.

**Питання:** Чим Node event loop відрізняється від browser rendering loop? Для чого EventEmitter? Що таке backpressure? Чому треба слухати `error` на WebSocket?

## Lab 05 — Authoritative Networking

- Сервер керує єдиною істинною симуляцією на 30 Hz. Клієнт відправляє input з `seq`, а не координати.
- Snapshots мають tick та `lastProcessedSeq`; `reconcile()` відновлює authoritative state і повторно застосовує pending inputs.
- `shared/src/codec/binary.ts` — DataView codec з magic/version, little-endian і quantized angle.
- У поточній версії є базовий snapshot flow і RTT ping/pong. Повний prediction/reconciliation у клієнтському render pipeline, remote interpolation buffer та latency/drop injector ще потрібно завершити перед заявою про повне виконання Lab 5.

**Питання:** Чому сервер authoritative? Що таке client-side prediction? Як працює reconciliation? Чому інші кораблі малюють із затримкою? Навіщо binary protocol?

## Lab 06 — TypeScript Contract

- Усі вихідні модулі — TypeScript; базова конфігурація strict + `noUncheckedIndexedAccess`.
- `shared/src/protocol/schema.ts` визначає Zod-схеми і типи з них. На межі мережі дані перевіряються в runtime — TypeScript типи самі по собі не існують у мережевому пакеті.
- `EntityKind`, `InputState`, `Snapshot` — типізовані структури.

**Питання:** Чому типи стираються в runtime? Для чого `unknown`? Чим discriminated union відрізняється від звичайного union? Що дає Zod?

## Lab 07 — Testing and Performance

- `shared/src/sim/world.test.ts` містить базові unit tests для Vector2, deterministic stepping, seeded PRNG, collisions і reconcile.
- `scripts/load-test.mjs` запускає WebSocket-клієнтів групами 8/32/64/128.
- Сервер експонує Prometheus metrics; Docker/CI workflow запускає typecheck, test і build.
- Вимога оригінальної лабораторної — щонайменше 60 тестів, 5 fast-check properties, shared coverage ≥85%, Playwright E2E у двох браузерних контекстах, before/after flame charts і виміряна capacity. Ці вимірювання потрібно ще виконати/розширити.

**Питання:** Чим unit test відрізняється від E2E? Що таке property-based testing? Як знайти GC hitch? Для чого object pooling? Як визначити server capacity?

## Lab 08 — Ship It

- Є Dockerfile, docker-compose, env-based config, `.env.example`, non-root runtime user, healthcheck і GitHub Actions workflows.
- Сервер має `/health`, `/ready`, `/metrics`, version stamp, structured JSON logs.
- Для реального релізу треба налаштувати GHCR/deploy secrets, ALLOWED_ORIGINS, HTTPS/WSS reverse proxy, протестувати shutdown у контейнері та зіграти матч двом користувачам з різних мереж.
- У PDF вимагається PWA install test, uptime monitor, demo video, реальний RTT та `v1.0.0` tag. Це зовнішні дії, які не можна правдиво позначити виконаними без запуску/облікових даних.

**Питання:** Що таке graceful shutdown? Чому WSS потрібен для HTTPS сайту? Для чого readiness окремо від liveness? Чому stateful WebSocket room не масштабується round-robin на кілька процесів?

## Запуск і демонстрація

```bash
cp .env.example .env
npm install
npm run dev
```

Відкрити `http://localhost:5173` у двох вікнах, ввести однакову кімнату й різні імена. Перевірити переміщення, постріли, чат, roster. API: `http://localhost:3000/health`, `/metrics`, `/api/rooms`.
